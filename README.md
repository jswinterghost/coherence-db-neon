# Coherence Database Core

Database-backed engine orchestration, immutable history ledger, separated code and data storage, historical importer, run comparator, downstream readers, and web API handlers for Coherence commission runs.

## What This Repository Provides

Each company runs in its own PostgreSQL 17 database (PostgreSQL is an open-source relational database management system) inside Nusear's cloud organization, paired with two strictly separated content-addressed object stores (storage buckets where each file is named by its SHA-256 cryptographic fingerprint, a 64-character hex digest computed from the file's exact bytes):

- **Nusear code store (`nusear_code`):** Holds sealed engine Git bundles (single-file repository archives), wrapper scripts, offline dependency manifests, and code-bearing HTML (Hypertext Markup Language) review pages and viewers. Customers never have access to this store.
- **Company data store (`company_data`):** Holds customer inputs, commission statements, approvals logs, working tables, and non-code data outputs. Code-bearing files are rejected at both storage and database boundaries.

Every business table is append-only (no `UPDATE`, `DELETE`, or `TRUNCATE`, even under database replication settings). Every change is recorded in a gapless, SHA-256 hash-chained journal whose commitments are checked by PostgreSQL triggers (database rules that run automatically during writes) before a transaction commits.

Release E1 separates Coherence reads into two clear areas, Release E2 enforces per-company user isolation and Nusear support boundaries, Release E3 models entities over time, and Release E4 unifies the role/right catalog, guards company revenue on agent roles while allowing own pay, and adds compliance per-NPN scoping:

- **The run workshop (all or nothing):** Runs, attempts, step and cancel requests, carries, abandonments, emit confirmations, review saves/configs/drafts/submissions, approval rows, decisions, decision commits, input versions/entries/changes and staging files, engine versions, checks, the journal, run stages, and unsent outputs are opened by one shared check (`app_views._read_workshop_right`), requiring both the matching workshop right (`runs.read`, `inputs.read`, `decisions.read`, `checks.read`, `journal.read`, or `outputs.read` for unsent outputs) and full-tenant `act:coherence.unpublished.read`. `app_views._read_has_run_meta_access()` and `app_views._read_can_see_unsent_run_meta()` count `runs.read` only through `app_views._read_workshop_right('act:coherence.runs.read')`, keeping the four finished-goods rights (`bob`, `statements`, `upline`, `ledger`) unchanged. Whoever passes sees all runs (unfinished included); whoever does not sees none of the workshop. Run stage calculation in `app_views.coherence_runs` delegates through a narrow `platform_readonly` `SECURITY DEFINER` wrapper (`coherence._ro_run_stage`) over `coherence.run_stage` with zero per-run rights or RLS work.
- **Finished goods:** The Book of Business, agency and upline statements, Coherent Ledger, reconciliation, sent outputs, and entity bundles remain scoped to sent runs for finished-goods readers (agency managers, agents, investors, and statements-only roles) through `app_views._read_published_emit_attempts` and `app_views.coherence_published_runs`.
- **Member data gates:** Across both finished goods and the workshop, member PHI (`col:coherence.member_phi`) and member contact details (`col:coherence.member_contact`) gate identifying columns, member-data file handles and checksums, free-text notes/reasons/conflicts/error summaries, `app_views.coherence_journal.body` (requiring full-tenant `member_phi`, and all eight entity-finance and member rights for both `carry_sent` and `materialize_emit`), and check `report` JSONB payloads (including run-less `import`, `overlay_reconstruction`, and `objects` reports, as well as `POST /checks/run` masked through `app_views.coherence_checks`), while whole-file Emit outputs, entity bundles, and sent carries require all eight tenant-wide rights via `app_views._read_has_full_entity_finance()`, verified by `tests/layer7_release_e1_member_rights.test.mjs` and `tests/layer7_release_e2_company_users_and_support.test.mjs`.
- **Full-tenant scope rule:** The workshop and whole-company outputs require the right over the whole company (every agency in its tree, history included), so an agency whose Coherence switch is `held` or `off` closes them to the company's own people while Nusear's people are unaffected, and company-anchored users plus Nusear staff remain open when archived or moved-out agencies exist. No customer grant reaches across companies through a holding company: the holding-company user-grant branch in `iam.person_effective_grants` is deleted in Release E2 (holding-company executives receive a separate user at each company).
- **Separate company users and Nusear support isolation (Release E2):** `iam.people` and `iam.person_versions` carry `principal_origin IN ('company_local', 'nusear_staff', 'service')` with per-origin unique live `primary_email` and `npn` so one real person can hold both a Nusear support identity and a company-local user in the same database without collision. Only `company_local` people resolve as `writing_person_id` (`coherence._resolve_writing_person_id()`, backfill, write commands, and the `ENABLE ALWAYS` `BEFORE INSERT OR UPDATE` `trg_guard_iam_fk_backfill` trigger across all five `writing_person_id` tables, while still allowing `NULL` for journal replays). `iam_secret.signing_keys` enables row-level security without `FORCE ROW LEVEL SECURITY` (restricting `platform_iam_sync` `SELECT`/`INSERT`/`UPDATE` strictly to `'nusear_staff'` and `'service'` keys while the table owner, sharing ownership with `iam.session_context()` and never `platform_iam_sync`, reads every key), and `iam_secret.signing_keys.key_scope` is verified in `iam.session_context()` so a company's web key cannot sign tokens for `nusear_staff` or `service` (worker) principals. Per-company sign-in identities (`iam.person_auth_identities`) map `(auth_issuer, auth_subject)` strictly to active `company_local` human users in that company's database via `iam.resolve_auth_identity()` executable solely by `platform_auth_lookup` (and owner `platform_readonly`), refusing suspended or revoked identities and users. Cross-origin role grants, cross-origin memberships, `company_local` rows in a `control` database, and `platform_iam_sync` reads or writes to `company_local` signing keys or writes to company-local people, affiliations, auth identities, or custom roles are refused inside PostgreSQL. `iam.assert_can_write()` records writes deterministically (`'self'` for `company_local`, `'nusear_support'` for `nusear_staff` in company databases, `'service'` for services), `app_cmd.coherence_record_decision_baseline` and `app_cmd.coherence_import_historical_run` stamp caller attribution on live baselines and UUID-spoofed rows while preserving non-UUID historical labels (leaving `acting_for` as carried, with omitted `decided_by` falling back to the caller in `coherence_record_decision_baseline` and `'historical_import'` in `coherence_import_historical_run`), and customer-facing views (`app_views.coherence_journal`, `app_views.coherence_decisions`, and `app_views.audit_journal`) show `'Nusear support'`, never the Nusear person's name or UUID, verified by `tests/layer7_release_e2_company_users_and_support.test.mjs`.
- **Entities over time (Release E3):** `iam.organizations.org_kind` stays immutable (each company runs its own database with its own tree, so a referral destination or agency becoming a Nusear customer gets its own database as `'company'`) and adds `'external_upline'` so an agency moving to a non-Nusear upline receives a dated live parent edge (`one parent per day` via `org_edges_one_parent_per_day`), keeping its historical chain in `iam.v_organization_closure` under the old company so runoff Emits reconcile to `$0.00` and its agency manager's reads keep working while the external upline sees zero rows (verified both with the external upline's `coherence` switch `'on'` and then `'off'`) and stays outside Coherence entity resolution and tool switches. `iam.organization_memberships` retires `capacity` in favor of plain dated works-for lines carrying nullable `work_arrangement IN ('employee', 'self_employed_internal', 'self_employed_external')` with no default (service principals and passive investors store `NULL`) and nullable `tax_classification IN ('w2', '1099')` (accounting tracking only, excluded from IAM evaluation), with `org_memberships_no_overlap` refusing overlapping active lines for the same `(person_id, organization_id)` and `iam.v_all_memberships_live` projecting `(person_id, organization_id, valid_range)`. `iam.organization_versions` adds `masked_display_name` (non-blank whenever non-NULL) and `trg_00b_verify_org_version` requires a non-blank `masked_display_name` on every `lead_vendor` organization version in each company's database (read-view masking comes in E5). `src/config/policy-checks.mjs` audits `PLATFORM_IAM_SYNC_FUNCTION_WHITELIST` (strictly the 5 `SECURITY INVOKER` helpers `platform_iam_sync` holds), refuses `platform_iam_sync` owning any function in any schema, and verifies `trg_00b_verify_org_version` is enabled, verified by `tests/layer7_release_e3_entities_over_time.test.mjs`.
- **Canonical role catalog, agents' own pay, and compliance by NPN (Release E4):** `src/iam/catalog.mjs` defines one canonical idempotent catalog (`CANONICAL_TOOLS`, `CANONICAL_RIGHTS`, `CANONICAL_ROLES`, and `seedIamCatalog()`) reused by `tests/helpers/iam-harness.mjs` and `scripts/prove-history.mjs` (covering owner, entity manager, administrator with the whole Coherence workshop and revenue/upline only if granted, agency manager, Director of Sales, Director of Operations, accounting, compliance, retention agent, selling agent, empty investor, Nusear support, Nusear owner, Nusear admin, and Coherence worker; any new role starts empty with zero rights until turned on). `iam.rights` adds sensitivity class `'hr_record'` and registers agent own-pay rights (`act:payroll.agent_pay.read`, `col:payroll.agent_pay_cash`, sensitivity class `money_pay`) for the pay tool to enforce when it joins PostgreSQL (no agent-pay data tables exist in this database yet). `iam.role_versions.forbids_company_revenue_rights` (set `true` on `selling_agent`, `retention_agent`, `compliance`, `director_of_sales`, and `director_of_operations`) is enforced bidirectionally by deferred constraint triggers (`trg_role_rights_verify_invariants` and `trg_role_versions_verify_invariants`), refusing `money_statement` and `money_upline` rights (`23514 COMPANY_REVENUE_RIGHT_FORBIDDEN`) while allowing agent own-pay `money_pay` and lead-cost `money_lead` rights. `iam.role_grants.person_scope_mode` adds `'explicit_people'` backed by append-only versioned table `iam.role_grant_people` (18th `iam.*` table, `SELECT`-only for `platform_iam_sync`, guarded by `trg_00b_verify_sync` and deferred `trg_role_grant_people_verify`), wired into `iam.person_effective_grants()`, single-evaluation `iam.effective_narrow_pairs()`, `iam.effective_any_org_ids()`, `iam.has_right()`, and `iam.assert_can_write()` so compliance users see strictly their permitted NPNs across Book of Business and zero-dollar agency statement lines (under View-as too) and revoking a person drops their rows immediately, verified by `tests/layer7_release_e4_roles_catalog_and_compliance.test.mjs`.

## Prerequisites

- Node.js 20 or newer

- Local PostgreSQL 17 server configured without `trust`, `md5`, or cleartext `password` authentication rules in `pg_hba.conf`

## Running Tests Against Local PostgreSQL 17

Tests create and drop throwaway databases strictly under the `coherence_test_*` prefix using in-memory object stores and synthetic fixtures. They never connect to cloud services or read member data folders.

1. Set the PostgreSQL connection variables for your local PostgreSQL 17 instance (`PGPORT` defaults to `5432` if omitted):

   ```sh
   PGHOST=/tmp PGPORT=5433 PGUSER="$USER" npm test
   ```

2. `npm test` runs in order:
   - JavaScript syntax check (`node --check` on every `.mjs` file)
   - `STATE_MACHINE.md` parity check against `src/state-machine/coherence-machines.mjs`
   - Layers 1 through 7 against live PostgreSQL 17
   - Repository clean-text hygiene check (`tests/clean-text.test.mjs`)

3. Useful individual commands:

   ```sh
   npm run check
   npm run docs:state-machine
   npm run docs:state-machine:check
   ```

## Read-Only History Proof Runner

To migrate a fresh throwaway local `test_*` database (pinning local PostgreSQL mode, strictly refusing non-local `PGHOST` values including any socket path under `/cloudsql` and non-`test_*` database names, verifying configured manifest folders exist, failing missing comparator targets by name, and cleaning its temporary folder on exit), import a company-agnostic JSON manifest read-only (with zero network calls), run Layers 0, 1, 2, and 4 plus the substance comparator where comparison targets exist, and print a strictly PHI-free summary:

```sh
PGHOST=/tmp PGPORT=5433 PGUSER="$USER" \
node scripts/prove-history.mjs --manifest /path/to/manifest.json --database test_history_proof
```

## Opt-In Live Import Proof

Default test runs never touch live run folders. Operators running a read-only historical import and rebuild proof against an external folder must opt in explicitly via environment variables:

```sh
COHERENCE_LIVE_PROOF=1 \
COHERENCE_REPO=/path/to/coherence \
NUSEAR_DATA_DIR=/path/to/nusear-data \
COHERENCE_PROOF_COMPANY=<company-slug> \
COHERENCE_PYTHON=/path/to/python \
PGHOST=/tmp PGPORT=5433 PGUSER="$USER" \
node --test tests/layer4_import_and_proofs.test.mjs
```
