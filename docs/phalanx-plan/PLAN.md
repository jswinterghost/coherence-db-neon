## 1. The Design in One Page

Phalanx is the first real implementation of Coherence as a database-backed web application inside Nusear's clean private repository (`nusear-platform`), built on the tested PostgreSQL 17 (a server-grade relational database system) prototype's cleaned branch (`worktrees/coherence-db-neon/reference/`). The design satisfies all six binding owner decisions of 2026-11-22 with the fewest moving parts `[doc, inference]`:

1. **Untouched reference, surgical Phalanx engine copy (~80 net lines across 5 files).** The original Coherence installation on the reference computer (`coherence/`) never changes by a single byte and remains the backup and reference ("the Bible"). Only Phalanx's own private copy of the engine (stored strictly in Nusear's private Git repository `coherence-engine` and Nusear's `nusear_code` object store, never in any customer repository, database, or bucket) receives two zero-substance-risk output changes: (a) writing plain JSON (JavaScript Object Notation, a structured text data format) review payloads (`bible.json`, `adjust.json`) instead of compiled HTML (Hypertext Markup Language, web page code) review pages; and (b) writing canonical data-only CSV (comma-separated values, a plain-text tabular format) outputs (`canonical_bob.csv`, `coherent_ledger.csv`, `statements_YYYYMMDD.csv`, companion admin CSVs, and `emit_metadata.json`) directly under `emits/` instead of building 102 per-recipient `viewer.html` bundles. Zero lines change in `coherence/overlay.py` or in any linking, attribution, diffing, settlement, split, Book of Business (BoB), or Coherent Ledger calculation module. Node, `pnpm` (a JavaScript package manager), Vite (a JavaScript web bundler), `company_emit.py`, `pages_law.py`, and all code-bearing artifacts disappear from new Phalanx runs. Linux portability (`ALL BOB` case handling and legacy encodings) stays deferred until the post-cutover Linux worker milestone so zero operating-system drift enters the takeover proof.
2. **Decisions are immutable database records; `overlay.csv` is a generated, fingerprinted artifact.** PostgreSQL holds every Bible and Adjust decision as an immutable row in a parent-linked commit chain (`coherence.decision_commits` plus `coherence.decisions`), recording the approval key (`record_id`), disposition and values, five approval-fact columns, actor, acting-for party, timestamp, run, review save, surface, and a database-verified `replaces_decision_id` pointer to the exact immediately preceding decision on that key. Live review screens post only new or changed decisions in JSON to a single `SERIALIZABLE` (PostgreSQL's strictest transaction isolation level, guaranteeing concurrent writes behave as if executed one at a time) transaction, retiring the prototype's asynchronous `review_submissions` CSV upload queue and closing the review-versus-Emit race structurally. Before running `bible`, `adjust`, or `emit`, the worker deterministically generates `input/Overlay/overlay.csv` (prior standing decisions) and `runs/<date>/overlay.csv` (prior plus this run's decisions) from those records, verifies them through Coherence's own reader, fingerprints them in `coherence.generated_overlays`, and passes them to `overlay.py` unchanged. Carrier input files stay files; carrying decisions advances a standing decision head without touching carrier `input_versions`.
3. **Canonical BoB, Coherent Ledger, and Entity Statements live in normalized, conservation-checked PostgreSQL tables and views.** Because the Coherent Ledger holds cumulative standing state only (omitting per-date actions, historical cancelled lines, pre-Coherence upline totals, and the 2026-08-01 override correction), each finished Emit atomically populates immutable tables for Canonical BoB (vertically split into zero-dollar `bob_policies` and 1:1 `bob_policy_financials`), Coherent Ledger (`coherent_ledger_rows`), and the chronological statement ledger (`statement_batches`, `statement_agency_lines`, and physically separate `statement_upline_lines`, backfilled once from the five pre-Coherence dates `2026-03-25` to `2026-07-31`, the `2026-08-01` correction, and the `2026-08-31` upline take-back). Views in `coherence_views` with `WITH (security_invoker = true, security_barrier = true)` produce each entity's statement per statement date and reproduce the 11/20 accounting exercise (10 dates, 70 files, 82,674 lines, `$1,063,019.51` cumulative ledger tie across all 8 entities). A deferred PostgreSQL trigger (a database rule that executes automatically at `COMMIT`) rejects any Emit where BoB-to-Ledger rollups or cumulative entity-statement-to-Ledger totals differ by even `$0.01`. Five dedicated `NOINHERIT`, `NOBYPASSRLS` read-only roles plus physical table walls, column grants, and fail-closed Row-Level Security (RLS, database rules restricting which rows a query may read) prevent cross-entity, upline, and dollar leaks when Phalanx's own people join after the owner-only launch.
4. **Native Nusear screens over one derived state machine, with six-layer substance proof and a fresh Switch Day.** Nine native screens follow Nusear's Coherence UI standard (Miller columns, multi-pane horizontal column browsers for navigating folder and record hierarchies; stacked drawers; Eastern Time labels; zero member identifiers in URLs) over the prototype's 11 derived run stages and 7 step attempt states, with both human review pauses strictly enforced. Before Switch Day, Phalanx's single cheap Cloud SQL PostgreSQL 17 instance inside Nusear's Google Cloud organization runs as Development (`dev.portal.nusear.com`, burnt amber `#C77700` strictly in 3 placements) while the untouched reference Mac stays Production and everyday tests run on local PostgreSQL 17 (port 5433). After closing all 21 active comment-pass shortcuts (deleting 1 superseded shortcut) plus 4 structural gaps and passing Layers 0 through 6 (including non-vacuous negative mutations and 11/20 entity-statement parity), Switch Day provisions a fresh Production database loaded solely from the reference computer's history (excluding the un-distributed `2026-11-11` exercise from standing `Sent/`), cuts over (`portal.nusear.com`, monochrome), and stops the old Development instance (`activationPolicy: NEVER`) whenever idle, with three lossless rollback windows back to the untouched reference Mac.

## 3. The Data: Decisions, Book, Ledger, Entity Statements, Permissions, and History Import

### 3.1 Decisions as First-Class Immutable Database Records

The prototype's file-centric `approvals_files`, `approval_rows`, and asynchronous `review_submissions` tables (`proto/migrations/001_schema.sql:189-231, 390-418` `[code]`) are replaced by four immutable business tables using a parent-linked commit DAG (directed acyclic graph, a linked chain of commits that supports parallel branches without loops) `[inference]`:

1. **`coherence.decision_commits`** (immutable batch header; establishes branch-safe lineage across both live runs and divergent historical branches):
   - `id UUID PRIMARY KEY` (UUID, Universally Unique Identifier, a 128-bit random identifier), `parent_commit_id UUID REFERENCES coherence.decision_commits(id)` (`CHECK (parent_commit_id IS NULL OR parent_commit_id <> id)`), `commit_kind TEXT NOT NULL CHECK (commit_kind IN ('review_save', 'historical_baseline', 'historical_overlay'))`, `header_contract TEXT NOT NULL DEFAULT 'v2' CHECK (header_contract IN ('v1', 'v2'))`, `added_decision_count INTEGER NOT NULL CHECK (added_decision_count >= 0)`, `cumulative_decision_count INTEGER NOT NULL CHECK (cumulative_decision_count >= added_decision_count)`, `added_decisions_sha256 TEXT NOT NULL CHECK (added_decisions_sha256 ~ '^[0-9a-f]{64}$')`, `imported BOOLEAN NOT NULL DEFAULT false`, `original_at TIMESTAMPTZ` (populated on imports; `NULL` on live commits), `journal_seq BIGINT NOT NULL REFERENCES coherence.journal_entries(seq)`.
2. **`coherence.decisions`** (every individual Bible and Adjust decision):
   - `id UUID PRIMARY KEY`, `decision_commit_id UUID NOT NULL REFERENCES coherence.decision_commits(id)`, `row_order INTEGER NOT NULL CHECK (row_order >= 1)` (`UNIQUE (decision_commit_id, row_order)`), `run_id UUID REFERENCES coherence.runs(id)`, `review_save_id UUID REFERENCES coherence.review_saves(id)`, `surface TEXT CHECK (surface IS NULL OR surface IN ('bible', 'adjust'))`, `record_id TEXT NOT NULL CHECK (pg_catalog.length(record_id) > 0)` (the approval key), `replaces_decision_id UUID REFERENCES coherence.decisions(id)` (`CHECK (replaces_decision_id IS NULL OR replaces_decision_id <> id)`).
   - Values: `disposition TEXT NOT NULL`, `agent TEXT`, `agency TEXT`, `policy TEXT`, `book TEXT`, `month TEXT`, `status TEXT`, `note TEXT`.
   - Five `overlay.py` v2 approval facts: `approved_amount TEXT`, `approved_agency TEXT`, `approved_agent TEXT`, `approved_agency_from TEXT`, `approved_agent_from TEXT`.
   - Provenance: `decided_by TEXT NOT NULL`, `acting_for TEXT`, `decided_at TIMESTAMPTZ NOT NULL`, `committed_at_raw TEXT` (verbatim ISO [International Organization for Standardization] timestamp string so regenerated overlays match reference rows verbatim), `imported BOOLEAN NOT NULL DEFAULT false`, `journal_seq BIGINT NOT NULL REFERENCES coherence.journal_entries(seq)`.
   - Live-decision `CHECK` constraints (when `imported = false`): `disposition IN ('CONFIRM', 'CORRECT')`; `run_id`, `review_save_id`, and `surface` all `NOT NULL`; amputated legacy columns `policy IS NULL AND month IS NULL`; `CONFIRM` carries zero acting fields (`agent, agency, book, status` all `NULL`) and `CORRECT` carries at least one non-null acting field; `status` is `NULL` or one of the 12 `PolicyStatus` enum literals (`coherence/status.py:76-100` `[code]`); `approved_amount` matches `^-?[0-9]+\.[0-9]{2}$` when non-null.
   - Indexes: `(record_id, journal_seq ASC, row_order ASC)`, `(decision_commit_id, row_order ASC)`, `(run_id, surface, row_order ASC)`, `(replaces_decision_id) WHERE replaces_decision_id IS NOT NULL`.
3. **`coherence.generated_overlays`** (immutable receipt of every `overlay.csv` generated from records for the engine; never source of truth):
   - `id UUID PRIMARY KEY`, `decision_commit_id UUID NOT NULL REFERENCES coherence.decision_commits(id)`, `run_id UUID NOT NULL REFERENCES coherence.runs(id)`, `purpose TEXT NOT NULL CHECK (purpose IN ('prior_input', 'bible_review', 'adjust_review', 'emit_output', 'historical_source'))`, `attempt_event_id UUID REFERENCES coherence.step_attempt_events(id)`, `header_contract TEXT NOT NULL CHECK (header_contract IN ('v1', 'v2'))`, `row_count INTEGER NOT NULL CHECK (row_count >= 0)`, `store_kind TEXT NOT NULL DEFAULT 'company_data' CHECK (store_kind = 'company_data')`, `file_sha256 TEXT NOT NULL` (composite FK to `stored_files(store_kind, sha256)`), `journal_seq BIGINT NOT NULL REFERENCES coherence.journal_entries(seq)`.
4. **`coherence.review_queue_items`** (lightweight immutable snapshot of `bible.csv` / `adjust.csv` loaded atomically when `bible` or `adjust` finishes):
   - Primary key `(attempt_event_id UUID, item_order INTEGER)`, `run_id UUID NOT NULL`, `surface TEXT NOT NULL CHECK (surface IN ('bible', 'adjust'))`, `record_id TEXT NOT NULL`, `case_kind TEXT`, `subtype TEXT`, `entity TEXT`, `npn TEXT`, `amount TEXT`, `entity_from TEXT`, `npn_from TEXT`, `needs_reconfirm BOOLEAN NOT NULL DEFAULT false`, `journal_seq BIGINT NOT NULL`.
   - Nested drawer evidence (`tx`, `cbob`, `sf`, `book_options`, `rows`) remains inside immutable `bible.json`/`adjust.json` in `company_data` and is served on demand per item via `POST` JSON body (avoiding an extra nested JSONB [PostgreSQL's binary-indexed JSON column format] evidence table while keeping 100% of PostgreSQL's queue-coverage and `reconfirm` validation).

**Database-enforced replacement chain (`trg_decision_commits_verify_deferred`):** At `COMMIT`, a single deferred trigger verifies: (1) `parent.journal_seq <= NEW.journal_seq` and `NEW.cumulative_decision_count = COALESCE(parent.cumulative_decision_count, 0) + NEW.added_decision_count`; (2) `decisions` count equals `NEW.added_decision_count`, `row_order` is contiguous `1..N`, every row shares `NEW.journal_seq`, and their canonical SHA-256 matches `NEW.added_decisions_sha256`; (3) a recursive CTE (Common Table Expression, a named SQL subquery that can reference itself) restricted strictly to the keys touched in `NEW.id` computes `LAG(id) OVER (PARTITION BY record_id ORDER BY depth DESC, row_order ASC)` and asserts `replaces_decision_id IS NOT DISTINCT FROM expected_prev_id` for every row `[inference]`. Thus the first decision on a key along any lineage must have `replaces_decision_id IS NULL`, and every revision must name the exact prior decision on that same key with zero skipped revisions or cross-branch pointers.

**Synchronous review save and deterministic overlay generation:**
- **Saving a review (`saveReviewDecisions`):** The browser posts ONLY this session's new or changed decisions as JSON (empty array allowed when all queue items are already covered, preserving both human pauses) with `commandKey` and `expectedJournalSeq`. One `SERIALIZABLE` PostgreSQL transaction verifies actor authorization (refusing `viewingAs` with `403`), idempotency, optimistic concurrency, 100% coverage of `review_queue_items`, and fresh in-run decisions for every `needs_reconfirm = true` Adjust item; resolves `replaces_decision_id`; inserts `journal_entries`, `decision_commits`, `review_saves` (pointing to `decision_commit_id`, deleting `review_drafts`), batched `decisions` (2,000-row `unnest` arrays), and on Bible supersedes any prior Adjust attempt and inserts `step_requests(step = 'adjust', reason = 'bible_saved')`. Operational table `review_submissions` is retired completely `[inference]`.
- **Generating `overlay.csv` (`src/decisions/overlay-generator.mjs`):** `generateOverlayCsv(db, decisionCommitId)` streams `coherence.decisions_in_commit(commitId)` (`ORDER BY depth DESC, row_order ASC`), writes the exact v1 (10-column) or v2 (15-column) header, serializes `NULL -> ""` and RFC 4180 CSV quoting with `\n` endings (matching Polars, the Python data-table library Coherence uses). Before running `bible`, `adjust`, or `emit`, `folder-builder.mjs` writes `input/Overlay/overlay.csv` from `run.prior_decision_commit_id` and (for `adjust` and `emit`) writes `runs/<date>/overlay.csv` from the latest Bible or Adjust `review_saves.decision_commit_id`, verifies the generated file via `coherence_overlay_check.py`, stores the bytes in `company_data`, and records the receipt in `coherence.generated_overlays`. Because browser exports used CRLF (Windows line endings) while Polars uses LF (Unix line endings), historical overlay parity is proved row for row and cell for cell across all 15 normalized columns through `coherence.overlay._read()` (`Amendment A8` `[doc, code]`).
- **Carrying decisions forward (`carries`):** `carries(carry_kind = 'decisions')` records `carried_decision_commit_id` and verifies `decision_commit_extends(run_commit, current_standing_head)` (`S-8`, preventing an older run from rolling back newer decisions). Carrier `input_versions` (`line_kind = 'standing'`, non-import) forbid `Overlay/` and `approvals/` entries: input files stay carrier sources and `Sent/` only `[inference]`.
- **Two "as of" time axes:** (1) Audit journal playback via `as_of_seq` or `as_of_recorded_at` (`standing_decision_head_as_of(seq)`, `decisions_in_commit(commit_id)`, `decisions_current(commit_id)`, `decisions_bible_applied(commit_id, bible_keys)`); and (2) historical business time via `COALESCE(original_at, je.recorded_at)` and `decisions.decided_at` so historical imports resolve cleanly by when the review originally happened `[inference]`.

### 3.2 Canonical Book of Business, Coherent Ledger, and Entity Statements

Seven immutable business tables (inserted atomically inside `finishStepAttempt` for `emit` in strict acyclic foreign-key order, all covered by `trg_immutable ENABLE ALWAYS`, `trg_01_require_active_journal`, and `trg_journal_verify_commitments`) eliminate row duplication while separating sensitive columns physically `[inference]`:

1. **`coherence.statement_batches`** (header for every dated statement batch): `id UUID PK`, `batch_kind IN ('historical_sent', 'method_correction', 'run_emission')`, `statement_date DATE`, `run_id UUID NULL`, `attempt_event_id UUID NULL`, `source_file_name TEXT`, `source_store_kind`, `source_file_sha256`, `reason TEXT`, `agency_line_count`, `agency_lines_sha256`, `agency_net_total NUMERIC(14,2)`, `upline_line_count`, `upline_lines_sha256`, `upline_net_total NUMERIC(14,2)`, `journal_seq BIGINT`.

**Entity Statement views and database-enforced conservation (`coherence_views`):**

- `v_statement_membership`: aggregates every statement appearance per `(policy_id, tx_id, record_id, statement_date)` straight from `statement_agency_lines` and `statement_upline_lines` (avoiding a separate duplicate membership table).
- `v_entity_statement_reconciliation(p_run_id UUID)`: compares cumulative `v_entity_statement_lines` across `v_run_effective_batches(p_run_id)` against `coherent_ledger_rows` for `p_run_id` per entity and per `record_id`.
