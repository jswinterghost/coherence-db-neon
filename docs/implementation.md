# Coherence Database Web App: Implementation Architecture

This guide explains how the codebase satisfies the requirements in `docs/requirements.md` and documents the key architectural decisions and verification layers.

## 1. Core Design Decisions

1. **Explicit UUID primary keys and gapless journal sequence:** Business entities use explicit UUID (Universally Unique Identifier) primary keys and `journal_entries` uses an explicit `BIGINT` `seq` (`1..N`). During NDJSON (newline-delimited JSON) journal export rebuilds, PostgreSQL verifies every supplied `seq`, `recorded_at`, `prev_hash`, and `entry_hash` rather than overwriting them.
2. **Composite `(store_kind, sha256)` key on `coherence.stored_files`:** Allows identical byte sequences (such as empty files) to exist independently in `nusear_code` and `company_data` while locking every foreign key structurally to the required store kind (`nusear_code` for engine versions and code-bearing artifacts; `company_data` for inputs, approvals, logs, and data artifacts).
3. **Two-argument session advisory lock plus `(pg_backend_pid(), own_backend_start())`:** Prevents operating-system process ID reuse bugs and guarantees only the exact worker database connection that started an attempt can record `finished`, `failed`, or `cancelled`, while allowing either a free slot or a replacement worker holding the slot on a new connection to reconcile a dead attempt as `interrupted`.
4. **Canonical JSON and UTC microsecond timestamps:** `coherence.canonical_json(jsonb)` in SQL and `canonicalJson()` in `src/util/crypto.mjs` sort object keys by UTF-8 byte order (`COLLATE "C"`) with zero insignificant whitespace. `src/db/pg-client.mjs` preserves raw PostgreSQL timestamp strings (`types.setTypeParser(1184/1114)`) so all 6 microsecond digits match identically between PostgreSQL and Node.
5. **All 30 child business tables hash-committed at `COMMIT`:** `src/commands/commitments.mjs` computes canonical row hashes for all 30 child business tables and embeds counts and hashes in `journal_entries.body.commitments`. A deferred `COMMIT` constraint trigger (`coherence.trg_journal_verify_commitments`) recomputes every count and hash inside PostgreSQL, while `created_xid = pg_current_xact_id()` prevents attaching rows to any already-committed journal entry.
6. **Decisions as immutable records with deterministic overlay generation:** `migrations/004_decisions_as_records.sql` stores decisions in a parent-linked commit chain (`coherence.decision_commits` and `coherence.decisions`) where `trg_decision_commits_verify_deferred` verifies exact `replaces_decision_id` pointers along the lineage via SQL `LAG`. `src/decisions/overlay-generator.mjs` deterministically renders `v1` (10-column) or `v2` (15-column) `overlay.csv` bytes as of any journal position matching `coherence/overlay.py`, and `coherence.generated_overlays` records the SHA-256 fingerprint of every generated file.
7. **Vertical Book of Business split, Coherent Ledger, entity statement views, and physical + RLS isolation:** `migrations/005_bob_ledger_and_statements.sql` and `migrations/006_entity_isolation_views_and_roles.sql` split the Canonical Book of Business into zero-dollar `bob_policies` and 1:1 `bob_policy_financials`, store 41-column `coherent_ledger_rows`, and physically separate `statement_agency_lines` from `statement_upline_lines`. `trg_run_materializations_verify_deferred` enforces `$0.00` variance across BoB-to-Ledger rollups and cumulative Entity-Statement-to-Ledger totals at `COMMIT`. Views in `coherence_views` use `WITH (security_invoker = true, security_barrier = true)` backed by `FORCE ROW LEVEL SECURITY` and five `NOINHERIT`, `NOBYPASSRLS` read-only roles.
8. **Declarative state machines as data:** `src/state-machine/declarative-machine.mjs` is a reusable library where states, transitions, guards, and database enforcement metadata are declared once as data. `src/state-machine/coherence-machines.mjs` declares both `RUN_STAGE_MACHINE` (11 derived stages, 18 transitions, 17 guards) and `STEP_ATTEMPT_MACHINE` (7 states, 6 transitions, 10 guards), driving static reachability validation, live PostgreSQL catalog verification (including strict `RETURN '<stage>'` literal verification in `coherence.run_stage`), and automated generation of `STATE_MACHINE.md`.
9. **Zero member data in URLs, logs, or error messages:** `src/util/redact.mjs` scrubs Coherence pipe-delimited record IDs (`carrier|channel|subject|amount|stamp`, including comma-joined `NM:` member tokens and `PN:` policy numbers), tilde record IDs (including spaces inside member names), policy keys, MBIs (Medicare Beneficiary Identifiers), SSNs, emails, phone numbers, and PostgreSQL `DETAIL`/`PARAMETERS` leak patterns. `src/web/router.mjs` rejects any URL path or query string containing `recordId`, `record_id`, or PHI patterns (`400`) and enforces `POST` JSON bodies for `/approvals/history` and `/decisions/history` (`GET` returns `405`). `python/coherence_overlay_check.py` prints error text only for controlled `OverlayValidationError` exceptions and emits a fixed generic message for all unexpected exceptions.
10. **Database-only IAM core (Release 1A, Migration 008):** `migrations/008_iam_core.sql` establishes the least-privilege `platform_*` `NOINHERIT` / `NOBYPASSRLS` roles (with `ALTER ROLE platform_app SET app.session_token = ''`, zero base-table privileges for `platform_app` on `iam`, `iam_secret`, and `platform`, and exact service-role `EXECUTE` grants for `platform_writer`, `platform_worker`, `platform_iam_sync`, and `platform_readonly`), the gapless SHA-256 hash-chained `platform.audit_journal`, `iam_secret.signing_keys` + pure-SQL RFC 2104 `iam_secret.hmac_sha256_hex()`, and all 22 append-only `iam.*` tables (9 strictly immutable tables including append-only `iam.right_retirements` guarded by `ENABLE ALWAYS` `platform.forbid_mutation()`, and 13 bitemporal versioned tables guarded by `ENABLE ALWAYS` `platform.guard_versioned_immutability()` + `platform.forbid_mutation()` on `TRUNCATE`, with `BEFORE INSERT` supersession stamped by `SECURITY DEFINER` `platform.stamp_superseded_before_insert()` owned by `platform_versioner` refusing duplicate `NEW.id` values and pairing `superseded_by_id` to the replacement's `replaces_id` via `UNIQUE (id, replaces_id)` and a `DEFERRABLE INITIALLY DEFERRED` composite foreign key so `INSERT ... ON CONFLICT DO NOTHING` can never orphan a live row). `iam.business_today()` evaluates calendar dates in `America/New_York`; `iam.session_context()` verifies signed `app.session_token` values with constant-time HMAC comparison, environment binding against `iam.database_context`, expiry, and live person status; set-theoretic `STABLE` helpers (`iam.effective_wide_org_ids`, `iam.effective_any_org_ids`, `iam.effective_narrow_pairs`, `iam.effective_narrow_person_ids`, `iam.effective_all_connection_org_ids`, `iam.effective_explicit_connection_pairs`, `iam.effective_explicit_connection_ids`, `iam.can_access_connection`, `iam.has_right`) enforce all four person scope modes, both connection scope modes, fail-closed NULL handling (`iam.can_access_connection()` returns strictly `false` on any NULL argument; omitted `p_data_date` matches only unrestricted grants where `data_date_range IS NULL`, so callers reading or writing dated records such as statements, ledger rows, BoB snapshots, calls, or transmittals must pass `p_data_date`), recursive organization/supervision closures (with deferred cycle rejection), nearest-ancestor tool switches where any ancestor `held` or `off` state vetoes every descendant (while Nusear-internal roles bypass customer switches), and View-as intersection; deferred constraint triggers enforce `allows_org_wide_scope` and the role delegation subset law (`iam.role_grantable_roles`, ignoring rights retired in `iam.right_retirements`); and `iam.assert_can_write()` rejects NULL/invalid `p_domain_kind` (`22023`), unconditionally refuses View-as (`42501 VIEW_AS_READ_ONLY` even in a `READ WRITE` transaction), fails closed on omitted `p_connection_id` for `explicit_connections` grants (callers writing connection-scoped records such as dialer/CRM/carrier connections, calls, or recordings must pass `p_connection_id`), and enforces each customer's `support_ceiling_role_id` (failing closed when NULL) on `customer_domain` writes while keeping `nusear_service` governed by Nusear internal roles. The separate Agent Register v1 backfill import is held outside this core pending its owner decision on whether roles without an explicit employment record should be refused rather than inferred.

## 3. Verification Strategy

The test suite is organized into seven risk-ranked layers ordered by worst cost of failure first, followed by a repository-wide clean-text hygiene check:

1. **Layer 1 (`tests/layer1_money_and_history.test.mjs`):** Protects financial correctness and immutable audit history (driver/env defaults and Cloud SQL IAM enforcement, immutability on all 31 business tables in normal and replica modes, journal chain forgery/gap/fork/backdate/multi-row/isolation refusals, batched writes and 30-table commitment hash verification, decision replacement chain and live CHECK refusals, deterministic `overlay.csv` round-trip and point-in-time playback, Emit materializer tie-out, NULL-split reversal unwinding, `$0.01` conservation refusal, duplicate-load refusal, input path/Sent/Overlay guards, duplicate sent statement and out-of-order carry refusals, and lossless NDJSON export/rebuild including point-in-time rebuild).
2. **Layer 2 (`tests/layer2_member_data_code_and_config.test.mjs`):** Protects member PHI confidentiality, cross-entity and zero-dollar isolation, Nusear code isolation, and security policy configuration (CRC32C/MD5 create-only storage, full-buffer code detection, redaction across logs/errors/URLs/Python stderr, View-As refusal on all write commands including `saveReviewDecisions`, worker-only exclusivity, `company_admin` read grants, customer-to-code isolation, `FORCE RLS` cross-entity isolation and `security_barrier` side-channel refusal across all 5 scoped roles, zero-dollar agent enforcement, sealed wrapper verification, exclusion of HTML from step workspaces, live catalog role/RLS/trigger/`search_path` audit, dynamic `SHOW hba_file` audit, and Cloud SQL policy validation).
3. **Layer 3 (`tests/layer3_state_machine_and_races.test.mjs`):** Protects workflow state integrity, concurrency safety, and worker fault recovery (static state-machine graph checks, strict SQL `RETURN` literal checks, `STATE_MACHINE.md` parity, live PostgreSQL walkthrough of all 11 run stages and 7 attempt states, synchronous `saveReviewDecisions` concurrency races, stale and duplicate save refusals, queue coverage and Adjust reconfirm enforcement, `carryDecisions` lineage enforcement, `engine_kind` registration, idempotency and staff permissions, slot mutual exclusion and out-of-transaction liveness, worker crash/reconciliation, grandchild process-group cancel/timeout, cancel-poll error escalation, and `EPERM` kill error reporting).
4. **Layer 4 (`tests/layer4_import_and_proofs.test.mjs`):** Protects historical import continuity, historical overlays into `decision_commits`/`decisions` with `replaces_decision_id`, deepest-ancestor divergent branch attachment, loud prefix-mismatch failure with run/checkpoint/row number, Layer 2 overlay reconstruction (`overlay_reconstruction` check), config-driven JSON manifests across all legacy/company/abandoned/environment/local-cloud-mirror/Incident-Report/8-table-SQLite sources, company-run sent provenance preservation, pre-Coherence 5 sent dates and 2 method corrections via `python/coherence_legacy_statements.py`, byte-for-byte Layer 1 rebuild and idempotency, on-demand working-table rebuild hash verification, parameterized Gates 1 to 4 substance comparison with planted-PHI exclusion, replay with recorded `born` write-back, CLI proof runner `scripts/prove-history.mjs`, and host-neutral opt-in live proof configuration.
