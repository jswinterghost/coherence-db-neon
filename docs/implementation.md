# Coherence Database Web App: Implementation Architecture

This guide explains how the codebase satisfies the requirements in `docs/requirements.md` and documents the key architectural decisions and verification layers.

## 1. Core Design Decisions

1. **Explicit UUID primary keys and gapless journal sequence:** Business entities use explicit UUID (Universally Unique Identifier) primary keys and `journal_entries` uses an explicit `BIGINT` `seq` (`1..N`). During NDJSON (newline-delimited JSON) journal export rebuilds, PostgreSQL verifies every supplied `seq`, `recorded_at`, `prev_hash`, and `entry_hash` rather than overwriting them.
2. **Composite `(store_kind, sha256)` key on `coherence.stored_files`:** Allows identical byte sequences (such as empty files) to exist independently in `nusear_code` and `company_data` while locking every foreign key structurally to the required store kind (`nusear_code` for engine versions and code-bearing artifacts; `company_data` for inputs, approvals, logs, and data artifacts).
3. **Two-argument session advisory lock plus `(pg_backend_pid(), own_backend_start())`:** Prevents operating-system process ID reuse bugs and guarantees only the exact worker database connection that started an attempt can record `finished`, `failed`, or `cancelled`, while allowing either a free slot or a replacement worker holding the slot on a new connection to reconcile a dead attempt as `interrupted`.
4. **Canonical JSON and UTC microsecond timestamps:** `coherence.canonical_json(jsonb)` in SQL and `canonicalJson()` in `src/util/crypto.mjs` sort object keys by UTF-8 byte order (`COLLATE "C"`) with zero insignificant whitespace. `src/db/pg-client.mjs` preserves raw PostgreSQL timestamp strings (`types.setTypeParser(1184/1114)`) so all 6 microsecond digits match identically between PostgreSQL and Node.
5. **All 19 child business tables hash-committed at `COMMIT`:** `src/commands/commitments.mjs` computes canonical row hashes for all 19 child tables and embeds counts and hashes in `journal_entries.body.commitments`. A deferred `COMMIT` constraint trigger (`coherence.trg_journal_verify_commitments`) recomputes every count and hash inside PostgreSQL, while `created_xid = pg_current_xact_id()` prevents attaching rows to any already-committed journal entry.
6. **Declarative state machines as data:** `src/state-machine/declarative-machine.mjs` is a reusable library where states, transitions, guards, and database enforcement metadata are declared once as data. `src/state-machine/coherence-machines.mjs` declares both `RUN_STAGE_MACHINE` (11 derived stages, 18 transitions, 16 guards) and `STEP_ATTEMPT_MACHINE` (7 states, 6 transitions, 10 guards), driving static reachability validation, live PostgreSQL catalog verification (including strict `RETURN '<stage>'` literal verification in `coherence.run_stage`), and automated generation of `STATE_MACHINE.md`.
7. **Zero member data in URLs, logs, or error messages:** `src/util/redact.mjs` scrubs tilde record IDs (including spaces inside member names), policy keys, MBIs (Medicare Beneficiary Identifiers), SSNs, emails, phone numbers, and PostgreSQL `DETAIL`/`PARAMETERS` leak patterns. `src/web/router.mjs` rejects any URL path or query string containing `recordId`, `record_id`, or PHI patterns (`400`) and enforces `POST` JSON bodies for `/approvals/history` (`GET` returns `405`). `python/coherence_overlay_check.py` prints error text only for controlled `OverlayValidationError` exceptions and emits a fixed generic message for all unexpected exceptions.

## 2. Requirement-to-Module Map

|---|---|---|
| Schema, immutability, journal chain, and commitments | `migrations/001_schema.sql`, `migrations/002_invariants_and_triggers.sql`, `src/commands/commitments.mjs`, `src/commands/journal-export.mjs` | `ENABLE ALWAYS` `trg_immutable` on all 20 business tables; `SERIALIZABLE` single-row journal inserts; deferred `COMMIT` verification of all 19 child table counts and canonical hashes; deterministic NDJSON export and verified rebuild. |

| Actors, permissions, and command layer | `src/commands/authz.mjs`, `src/commands/command-layer.mjs` | Single write chokepoint; View-As write refusal; strict `worker`-only command boundary; explicit per-area read grants for `company_admin` (`inputs`, `runs`, `outputs` only); `commandKey` idempotency with payload/actor conflict refusal; `expectedJournalSeq` optimistic concurrency; 2,000-row batched `unnest` inserts. |

## 3. Verification Strategy

The test suite is organized into five risk-ranked layers ordered by worst cost of failure first, followed by a repository-wide clean-text hygiene check:

1. **Layer 1 (`tests/layer1_money_and_history.test.mjs`):** Protects financial correctness and immutable audit history (driver/env defaults and Cloud SQL IAM enforcement, immutability on all 20 business tables in normal and replica modes, journal chain forgery/gap/fork/backdate/multi-row/isolation refusals, batched writes and 19-table commitment hash verification, input path/Sent/Overlay guards, duplicate sent statement and out-of-order carry refusals, and lossless NDJSON export/rebuild).
2. **Layer 2 (`tests/layer2_member_data_code_and_config.test.mjs`):** Protects member PHI confidentiality, Nusear code isolation, and security policy configuration (CRC32C/MD5 create-only storage, full-buffer code detection, redaction across logs/errors/URLs/Python stderr, View-As refusal, worker-only exclusivity, `company_admin` read grants, customer-to-code isolation, sealed wrapper verification, exclusion of HTML from step workspaces, live catalog role/trigger/`search_path` audit, dynamic `SHOW hba_file` audit, and Cloud SQL policy validation).
3. **Layer 3 (`tests/layer3_state_machine_and_races.test.mjs`):** Protects workflow state integrity, concurrency safety, and worker fault recovery (static state-machine graph checks, strict SQL `RETURN` literal checks, `STATE_MACHINE.md` parity, live PostgreSQL walkthrough of all 11 run stages and 7 attempt states, idempotency and staff permissions, tab/review/Emit races, slot mutual exclusion and out-of-transaction liveness, worker crash/reconciliation, grandchild process-group cancel/timeout, cancel-poll error escalation, and `EPERM` kill error reporting).
4. **Layer 4 (`tests/layer4_import_and_proofs.test.mjs`):** Protects historical import continuity, byte-for-byte rebuild, on-demand working-table rebuild hash verification, Python-only overlay parsing, Git commit archiving failures, corrupt SQLite refusal, config-driven company import profiles, input-first run comparison (`trial`, `entity_mapped`, and `substance` takeover mode), replay with recorded `born` write-back, and host-neutral opt-in live proof configuration.
5. **Layer 5 (`tests/layer5_screens_and_readers.test.mjs`):** Protects downstream readers, signed no-dollar agent feeds, entity-bundle ambiguity detection, web endpoints, "as of" history, non-sandboxed headers, refusal of dropped per-recipient bundle paths, and fail-closed review-app drift detection.
6. **Clean Text (`tests/clean-text.test.mjs`):** Scans every kept repository file to ensure zero personal names, tool or model names, workstation paths, em dashes, or customer names inside `src/`.
