# Coherence Database Web App: Implementation Architecture

This guide explains how the codebase satisfies the requirements in `docs/requirements.md` and documents the key architectural decisions and verification layers.

## 1. Core Design Decisions

1. **Explicit UUID primary keys and gapless journal sequence:** Business entities use explicit UUID (Universally Unique Identifier) primary keys and `journal_entries` uses an explicit `BIGINT` `seq` (`1..N`). During NDJSON (newline-delimited JSON) journal export rebuilds, PostgreSQL verifies every supplied `seq`, `recorded_at`, `prev_hash`, and `entry_hash` rather than overwriting them.
2. **Composite `(store_kind, sha256)` key on `coherence.stored_files`:** Allows identical byte sequences (such as empty files) to exist independently in `nusear_code` and `company_data` while locking every foreign key structurally to the required store kind (`nusear_code` for engine versions and code-bearing artifacts; `company_data` for inputs, approvals, logs, and data artifacts).
3. **Two-argument session advisory lock plus `(pg_backend_pid(), own_backend_start())`:** Prevents operating-system process ID reuse bugs and guarantees only the exact worker database connection that started an attempt can record `finished`, `failed`, or `cancelled`, while allowing either a free slot or a replacement worker holding the slot on a new connection to reconcile a dead attempt as `interrupted`.
4. **Canonical JSON and UTC microsecond timestamps:** `coherence.canonical_json(jsonb)` in SQL and `canonicalJson()` in `src/util/crypto.mjs` sort object keys by UTF-8 byte order (`COLLATE "C"`) with zero insignificant whitespace. `src/db/pg-client.mjs` preserves raw PostgreSQL timestamp strings (`types.setTypeParser(1184/1114)`) so all 6 microsecond digits match identically between PostgreSQL and Node.
5. **All 30 child business tables hash-committed at `COMMIT`:** `src/journal/commitments.mjs` computes canonical row hashes for all 30 child business tables and embeds counts and hashes in `journal_entries.body.commitments`. A deferred `COMMIT` constraint trigger (`coherence.trg_journal_verify_commitments`) recomputes every count and hash inside PostgreSQL, while `created_xid = pg_current_xact_id()` prevents attaching rows to any already-committed journal entry.
6. **Decisions as immutable records with deterministic overlay generation:** `migrations/004_decisions_as_records.sql` stores decisions in a parent-linked commit chain (`coherence.decision_commits` and `coherence.decisions`) where `trg_decision_commits_verify_deferred` verifies exact `replaces_decision_id` pointers along the lineage via SQL `LAG`. `src/decisions/overlay-generator.mjs` deterministically renders `v1` (10-column) or `v2` (15-column) `overlay.csv` bytes as of any journal position matching `coherence/overlay.py`, and `coherence.generated_overlays` records the SHA-256 fingerprint of every generated file.
7. **Vertical Book of Business split, Coherent Ledger, entity statement views, and physical + RLS isolation:** `migrations/005_bob_ledger_and_statements.sql` and `migrations/009_coherence_under_iam.sql` (`006_entity_isolation_views_and_roles.sql` retired) split the Canonical Book of Business into zero-dollar `bob_policies` and 1:1 `bob_policy_financials`, store 41-column `coherent_ledger_rows`, and physically separate `statement_agency_lines` from `statement_upline_lines`. `trg_run_materializations_verify_deferred` enforces `$0.00` variance across BoB-to-Ledger rollups and cumulative Entity-Statement-to-Ledger totals at `COMMIT`. Security-barrier views in `app_views.*` (owned by `NOBYPASSRLS` `platform_view_owner`) backed by IAM `FORCE ROW LEVEL SECURITY` and least-privilege `platform_*` roles enforce row and column isolation (pre-IAM `coherence_views.*` and `coherence_*_ro` roles are retired).
8. **Declarative state machines as data:** `src/state-machine/declarative-machine.mjs` is a reusable library where states, transitions, guards, and database enforcement metadata are declared once as data. `src/state-machine/coherence-machines.mjs` declares both `RUN_STAGE_MACHINE` (11 derived stages, 18 transitions, 17 guards) and `STEP_ATTEMPT_MACHINE` (7 states, 6 transitions, 10 guards), driving static reachability validation, live PostgreSQL catalog verification (including strict `RETURN '<stage>'` literal verification in `coherence.run_stage`), and automated generation of `STATE_MACHINE.md`.
9. **Zero member data in URLs, logs, or error messages:** `src/util/redact.mjs` scrubs Coherence pipe-delimited record IDs (`carrier|channel|subject|amount|stamp`, including comma-joined `NM:` member tokens and `PN:` policy numbers), tilde record IDs (including spaces inside member names), policy keys, MBIs (Medicare Beneficiary Identifiers), SSNs, emails, phone numbers, and PostgreSQL `DETAIL`/`PARAMETERS` leak patterns. `src/web/router.mjs` rejects any URL path or query string containing `recordId`, `record_id`, or PHI patterns (`400`) and enforces `POST` JSON bodies for `/approvals/history` and `/decisions/history` (`GET` returns `405`). `python/coherence_overlay_check.py` prints error text only for controlled `OverlayValidationError` exceptions and emits a fixed generic message for all unexpected exceptions.
10. **Database-only IAM core (Release 1A + Release E2 + Release E3 + Release E4, Migration 008) and canonical catalog (`src/iam/catalog.mjs`):** `migrations/008_iam_core.sql` establishes 9 least-privilege `platform_*` `NOINHERIT` / `NOBYPASSRLS` roles (`platform_view_owner`, `platform_writer`, `platform_versioner`, `platform_app`, `platform_worker`, `platform_iam_sync`, `platform_readonly`, `platform_migrator`, and `platform_auth_lookup`, with `ALTER ROLE platform_app SET app.session_token = ''`, zero base-table privileges for `platform_app` and `platform_auth_lookup` on `iam`, `iam_secret`, and `platform`, and `platform_auth_lookup` restricted strictly to `EXECUTE` on `iam.resolve_auth_identity(text, text)`), the gapless SHA-256 hash-chained `platform.audit_journal`, scoped `iam_secret.signing_keys` (`key_scope IN ('company_local', 'nusear_staff', 'service')`, guarded by non-forced `ENABLE ROW LEVEL SECURITY` limiting `platform_iam_sync` to `'nusear_staff'` and `'service'` keys while the shared owner of `iam_secret.signing_keys` and `iam.session_context()` reads every key, plus `trg_00_verify_signing_key_sync`) + pure-SQL RFC 2104 `iam_secret.hmac_sha256_hex()`, and 18 append-only `iam.*` tables (7 strictly immutable tables including `iam.organizations` with immutable `org_kind` covering `'external_upline'`, `iam.rights` adding sensitivity class `'hr_record'`, and append-only `iam.right_retirements` guarded by `ENABLE ALWAYS` `platform.forbid_mutation()`, and 11 bitemporal versioned tables including `iam.organization_versions` carrying `masked_display_name` enforced non-blank on `lead_vendor` rows by `trg_00b_verify_org_version`, `iam.organization_memberships` carrying dated works-for lines with nullable `work_arrangement` (no default; service principals and passive investors store `NULL`) + nullable `tax_classification` and `(person_id, organization_id, valid_range)` non-overlap exclusion, `iam.person_auth_identities`, `iam.role_versions` carrying `forbids_company_revenue_rights` enforced bidirectionally with `iam.role_rights` via deferred `trg_role_versions_verify_invariants` and `trg_role_rights_verify_invariants` forbidding `money_statement`/`money_upline` while allowing agent own-pay `money_pay` and `money_lead`, and `iam.role_grant_people` supporting `person_scope_mode = 'explicit_people'` with `trg_00b_verify_sync` and deferred `trg_role_grant_people_verify`, all guarded by `ENABLE ALWAYS` `platform.guard_versioned_immutability()` + `platform.forbid_mutation()` on `TRUNCATE`, with `BEFORE INSERT` supersession stamped by `SECURITY DEFINER` `platform.stamp_superseded_before_insert()` owned by `platform_versioner`). `iam.people` and `iam.person_versions` carry `principal_origin IN ('company_local', 'nusear_staff', 'service')` with composite FK parity and origin-scoped live email and NPN unique indexes; origin/role/control-DB/`platform_iam_sync` triggers enforce strict separation between company-local users and mirrored Nusear staff (with `platform_iam_sync` holding zero `INSERT` on `agent_affiliations` and `role_grant_people` and zero privileges on `person_auth_identities`). `src/iam/catalog.mjs` defines the single canonical idempotent catalog (`CANONICAL_TOOLS`, `CANONICAL_RIGHTS`, `CANONICAL_ROLES`, and `seedIamCatalog()`, preserving explicit revocations on re-seed and registering agent own-pay rights for the pay tool when its tables join PostgreSQL), reused by `tests/helpers/iam-harness.mjs` and `scripts/prove-history.mjs`. Features not needed yet (supervision links, connection scopes, role-delegation law triggers, person contacts, and contractor ceiling) remain parked until needed. `iam.business_today()` evaluates calendar dates in `America/New_York`; `iam.session_context()` verifies signed `app.session_token` values with constant-time HMAC comparison, environment binding against `iam.database_context`, signing-key `key_scope` against actor `principal_origin` (and View-as scope bounds), expiry, and live person status. One unified evaluator (`iam.v_organization_closure`, `iam.v_organization_closure_live`, and `iam.person_effective_grants`) enforces strict company-database tenant bounding with zero cross-company holding-company grant flow, archived-path descendant visibility strictly from active ancestors with `include_descendants = true` `org_subtree` grants, dated ranges, full-path tool switches (ancestor `held`/`off` veto with Nusear-internal bypass), right retirements, and View-as intersection across `org_subtree`, `self`, and `explicit_people` scope modes. `iam.assert_can_write(p_right_id, p_record_org_id, p_subject_person_id, p_data_date)` enforces active action rights, refuses writes on archived paths, refuses View-as unconditionally (`42501 VIEW_AS_READ_ONLY`), and records `recorded_as` deterministically from `principal_origin` (`'self'`, `'nusear_support'`, or `'service'`). The separate Agent Register v1 backfill import remains held pending its owner decision.
